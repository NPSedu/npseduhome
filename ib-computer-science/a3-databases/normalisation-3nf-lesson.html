Model answer:

3NF: Non-key attributes do not depend on other (transitive) non-key attributes.

Quick reference

Normalisation
Organising data into two or more related tables, linked by keys, so redundancy is minimised.
Atomic
A single, indivisible value — one value per cell, no lists.
1NF
No repeating groups; every value is atomic.
2NF
The table is in 1NF and every non-key attribute depends on the whole primary key (no partial dependency).
3NF
The table is in 2NF and no non-key attribute depends on another non-key attribute (no transitive dependency).
Composite key
A primary key made of two or more attributes combined.
Partial dependency
A non-key attribute depends on only part of a composite key.
Transitive dependency
A non-key attribute depends on another non-key attribute, not directly on the primary key.
Update anomaly
Redundant copies of data become inconsistent when only one copy is updated.
